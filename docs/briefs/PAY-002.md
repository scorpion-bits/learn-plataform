# PAY-002 — Cliente AbacatePay + checkout PIX

**Agente:** A07 Payments · **Modelo:** Opus 5.5 · **Esforço:** alto

## Objetivo
Aluno logado inicia a compra de um curso: o servidor cria o pedido com o preço do banco, gera a cobrança PIX transparente no AbacatePay e leva o aluno à página do pedido (que mostrará o QR — PAY-004). **Nenhum acesso é concedido aqui.**

## Entregas
- `src/lib/payments/abacatepay.ts` (`server-only`): `createPixCharge({ orderId, amountCents, description, customer, expiresInSeconds })` e `getPixStatus(billingId)`; `fetch` com timeout (AbortController ~10 s), envelope `{data,success,error}` validado com zod (só campos usados), erros mapeados para tipos (`provider_unavailable`, `invalid_request`, `unauthorized`); nunca logar chave, CPF completo ou payload pessoal. Interface pequena (ADR-016) — sem abstração multi-provedor.
- `src/lib/payments/tax-id.ts`: validação de CPF (dígitos verificadores) + telefone BR; testes.
- `src/features/checkout/{schemas,actions,queries}.ts`:
  - `startCheckout({ courseSlug, taxId, phone })` via `userAction`:
    1. curso publicado com `price_cents > 0` (senão erro amigável);
    2. usuário sem acesso ativo ao curso (`has_course_access` via RPC com client do usuário) → senão erro "Você já possui este curso" com link;
    3. salva `tax_id`/`phone` no próprio perfil (client do usuário);
    4. reaproveita pedido `pending` não expirado do mesmo usuário+curso (com `pix_br_code` presente) → redireciona para ele;
    5. senão cria `orders` (status `pending`, `source='checkout'`, `provider='abacatepay'`, `amount_cents` do banco) com o **service client** — `user_id` sempre da sessão; trate a corrida do índice único de pending (23505 → reler e reaproveitar);
    6. chama `createPixCharge` (`externalId = order.id`, `expiresIn` 3600) e grava `provider_billing_id`, `pix_br_code`, `pix_br_code_base64`, `expires_at`; se o provedor falhar, marque o pedido `failed` (ou `canceled`) e retorne erro amigável sem vazar detalhes;
    7. `redirect('/checkout/pedido/<orderId>')`.
- `/checkout/[slug]` (`src/app/(checkout)/checkout/[slug]/page.tsx` ou dentro de `(student)` — use o grupo que já tem `requireUser`; documente): resumo do curso (capa, título, preço), formulário CPF + telefone (prefill do perfil, máscara leve, `inputMode="numeric"`, `autoComplete`), aviso de política de reembolso de 7 dias (link `/termos`), botão "Gerar PIX" com `pending`. Mobile-first, teclado, erros por campo.
- `/checkout/pedido/[orderId]`: **placeholder mínimo** que só confirma que o pedido é do usuário (RLS) e mostra status — a página completa é PAY-004.
- `.env.example`: só comentários se faltar algo (não criar novas envs sem necessidade).
